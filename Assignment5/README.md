# Assignment 5 — Synthetic Data Quality Audit

## Purpose

This Assignment 5 audit evaluates whether the Development Dataset can support credible testing of the team's bounded complaint-routing capability.

The governing question is:

> What data will permit credible testing and adaptation?

The bounded capability is employee-assisted routing, escalation, and human-review support for web-submitted credit-card billing disputes.

---

## 1. Data Scope

The scoped development cohort contains 653 records satisfying:

- Product = Credit card
- Issue = Billing disputes
- Submitted via = Web

The primary predictive input is:

- `consumer_complaint_narrative`

Target/reference outputs include:

- `routing_destination`
- `escalation_required`
- `human_review_required`
- `recommended_next_action`
- `fraud_indicator`

The following fields are excluded from predictive input because they are targets, references, labels, or potentially leakage-prone metadata:

- `routing_destination`
- `escalation_required`
- `human_review_required`
- `recommended_next_action`
- `fraud_indicator`
- `label_status`
- `label_confidence`
- `special_case_flags`

---

## 2. Key Data Quality Findings

Five consequential limitations were identified:

1. **Synthetic instructional labels are not bank ground truth.**  
   The operating labels were created for the course PoC and should not be interpreted as verified bank operational outcomes.

2. **Label ambiguity is substantial.**  
   Within the 653-case cohort:
   - Clear: 401
   - Judgment Required: 237
   - Insufficient Evidence: 15

3. **Target/surrogate leakage is a material risk.**  
   `fraud_indicator` is strongly associated with routing, and `escalation_required` is structurally associated with `human_review_required`. These fields must remain outside predictive inputs.

4. **The scoped cohort has no Low-urgency cases.**  
   This limits confidence in evaluating model behavior across the full urgency range.

5. **`sub_product` and `sub_issue` are completely missing in the scoped cohort.**  
   Both fields are missing for all 653 scoped cases, limiting analysis based on those dimensions.

---

## 3. Fitness Judgment

### FIT WITH CONTROLS / LIMITATIONS

The Development Dataset is suitable for a bounded instructional PoC, provided that the limitations above remain explicit.

The most important limitation is that the synthetic operating labels are not verified bank ground truth. Therefore, agreement between a model and these labels would demonstrate consistency with the course labeling scheme, not real-world bank operational correctness.

Additional controls are required for:

- input/target separation;
- leakage prevention;
- interpretation of ambiguous labels;
- coverage limitations;
- missing sub-product/sub-issue information.

## 9. Independent Professional Judgment

The Development Dataset is appropriate for a bounded instructional PoC **with controls and explicit limitations**.

The limitation that most constrains the strength of the evidence is the absence of verified bank ground truth for the synthetic operating labels. The dataset can support testing of consistency with the course-defined labeling scheme, but it cannot by itself establish that the resulting routing or escalation behavior would be correct in a real bank environment.

---

## 10. Self-Reflection

A simple dataset summary would have shown the row count and overall label distribution, but it would not have exposed several issues that materially affect confidence in the evidence. The scoped cohort contains substantial judgment-required cases, no Low-urgency cases, and complete missingness for both `sub_product` and `sub_issue`. The leakage analysis also showed that some reference fields are closely tied to target outcomes and therefore cannot safely be treated as model inputs. Most importantly, the audit clarified that the operating labels are synthetic instructional labels rather than verified bank ground truth. This changed my confidence from treating the dataset as broadly representative to treating it as useful for a bounded PoC only when these controls and limitations remain explicit.
